# ALCF-V0 Implementation Design

**Date:** 2026-09-13  
**Repository:** `bjoern-janson/adaptive-leverage`  
**Scientific authority:** the frozen ALCF-V0 preregistration and machine-readable protocol  
**Design status:** implementation design; no assay execution or scientific result

## 1. Purpose and non-goals

The implementation exists to instantiate the already-frozen ALCF-V0 protocol without changing its semantics. It is deliberately small, deterministic, and inspectable. Its job is to make the preregistered causal chain executable, preserve arm and custody provenance, emit an append-only trace, and mechanically classify outcomes under the frozen stop/null/positive rules.

The implementation does not redesign the assay, add scientific arms, choose a scalar corrigibility metric, broaden the claim ceiling, or execute the scientific assay in the same commit that lands the mechanism. It also does not infer a result from endpoint behavior alone.

## 2. Approaches considered

### Approach A — single monolithic script

One script could construct the machine, intervene, trace, and classify. This is minimal in file count but weak in auditability: transition semantics, custody, trace hashing, and classification would be entangled, making it harder to determine whether a positive classification came from the machine or the classifier.

### Approach B — small typed modules with a pure classifier (**selected**)

Separate the finite machine, interventions/custody, trace construction, and classification into focused modules. Keep all behavior deterministic and represent states/events as immutable data. This adds modest structure but gives clean audit boundaries and lets tests independently establish transition semantics, custody rules, and decision rules.

### Approach C — generic experiment framework

Build reusable abstractions for arbitrary worlds, arms, policies, and route graphs. This would overgeneralize before the first assay exists and introduce implementation degrees of freedom not licensed by the frozen protocol.

**Decision:** Approach B. It is the smallest structure that keeps the causal claim inspectable without turning V0 into a framework project.

## 4. Core data model

`model.py` will encode exactly the finite tuple frozen by the protocol:

```text
phase
policy_mode
warrant_status
authority_status
compiled_mode
scope_status
```

All protocol symbols (`w_n`, `w_c`, `o_n`, `o_c`, `e_star`, `c_star`, `omega_star`, `a0`, `a1`) are explicit constants rather than free-form strings supplied by callers.

Machine transitions are pure functions: state plus registered input produces a new state and one trace event. No hidden global state, wall-clock time, randomness, network access, or environment-dependent behavior is allowed.

The normal dynamic route and contradiction route must implement the frozen `E1`–`E6` chain exactly. The A-arm compiled dispatch is represented separately as `E5A`; it must not be silently normalized into `E5` or `E6` by tracing code.

## 5. Capability intervention and custody

The A-arm optimization step is intentionally tiny and must be reproducible from the normal workload alone. The compiler receives only the allowed normal transcript/cost material frozen by the protocol and produces a compiled dispatch artifact.

The compiler API must make forbidden access structurally difficult: corrective artifacts are not arguments to the compile function and are not present in the normal-workload input object. The build records a canonical input manifest and SHA-256 hashes of all allowed inputs, then hashes the finalized compiled artifact before any corrective replay object is supplied to the assay runner.

A custody validator independently checks:

- only allowed normal-workload artifacts appear in the optimization manifest;
- no forbidden corrective symbol or corrective replay representation appears in compiler inputs;
- the compiled artifact has a finalization hash before corrective replay;
- intervention provenance is `COMPILE_DISPATCH`.

Failure yields `OPTIMIZATION_LEAKAGE`; it never degrades into a positive foreclosure classification.

## 6. Arm construction

The authoritative initial machine `M0` is immutable. The precheck runs on a sacrificial clone. After precheck passes, `C`, `A`, and `E` fork from byte-identical serialized snapshots of `M0`.

- `C`: `NOOP`; `compiled_mode=0`; `scope_status=OPEN`.
- `A`: normal-workload-only `COMPILE_DISPATCH`; `compiled_mode=1`; `scope_status=OPEN`.
- `E`: `VALID_SCOPE_CLOSURE`; `compiled_mode=0`; `scope_status=CLOSED_VALID`.

The fork serializer is canonical so byte identity is testable rather than asserted informally.

## 7. Trace and provenance

`trace.py` emits canonical JSON-compatible event objects containing every field required by the frozen trace schema. Serialization uses sorted keys, UTF-8, no insignificant whitespace, and deterministic value encodings.

Each event hash is:

```text
event_sha256 = SHA256(canonical_json(event_without_event_sha256))
```

and `prev_event_sha256` must equal the preceding event hash, or `null` for sequence zero.

Trace validation is separate from machine execution. The validator rejects missing fields, broken sequence order, broken hash chains, unknown edge IDs, or unknown provenance values.

## 8. Assay flow

`assay.py` exposes execution primitives but the implementation commit does not include a committed scientific result.

The deterministic flow is:

```text
verify frozen protocol hash
        ↓
instantiate M0
        ↓
sacrificial contradiction precheck
        ↓
verify E1→E2→E3→E4→E5→E6 and a1
        ↓
fork byte-identical C / A / E
        ↓
construct A from frozen normal workload only
        ↓
finalize + hash A intervention
        ↓
run frozen normal workload for capability measurement
        ↓
replay identical corrective condition in C / A / E
        ↓
validate traces
        ↓
classify mechanically
```

The future execution step may serialize custody and trace artifacts, but result artifacts are not preregistered retroactively and cannot alter the frozen protocol.

## 9. Capability measurement

The capability metric is exactly the frozen V0 efficiency criterion: correct `a0` output on the deterministic normal workload at lower causal micro-transition cost.

No secondary performance metric is introduced. If A does not return `a0`, or if its cost is not strictly lower than C, classification is `NO_CAPABILITY_GAIN` with no foreclosure inference.

## 10. Route reachability and edge localization

A qualified corrective path must reach, in order, `e_star`, `CORRECTION`, `CORR_AUTH`, `CORRECTED`, and `a1` through the frozen causal chain.

The implementation computes route status from the trace; it does not infer reachability from final action alone. If `R_A` is empty, the localization routine compares the observed trace to the frozen `E1`–`E6` sequence and returns the unique first missing frozen edge. No unique edge means `TRACE_AMBIGUOUS`.

The frozen expectation is `E5`; this is an expectation, not the definition of a positive result. The classifier consumes the observed localization.

## 11. Mechanical classifier

`classify.py` is a pure function over validated assay observations and custody facts. It encodes the frozen precedence of stop/invalid/null/positive rules rather than using narrative interpretation.

At minimum it must distinguish:

```text
PRECHECK_FAIL
IDENTITY_MISMATCH
CONTROL_MISMATCH
POSITIVE_CONTROL_FAIL
OPTIMIZATION_LEAKAGE
NO_CAPABILITY_GAIN
WARRANT_DRIFT
TRACE_AMBIGUOUS
NULL_ROUTE_PRESERVED
POSITIVE_ADAPTIVE_FORECLOSURE
```

A positive classification is unreachable unless all preregistered conjuncts hold: capability gain, custody passed, warrant preserved, C route nonempty, A route empty, unique missing edge, `COMPILE_DISPATCH` ancestry for route loss, and no licensing epistemic event.

## 12. Error handling

Protocol violations are typed classification outcomes, not exceptions, when they are part of the frozen decision table. Programming errors, malformed internal data, or impossible enum values raise implementation errors and invalidate the run rather than being mapped to scientific outcomes.

No exception handler may convert a software fault into a null or positive scientific classification.

## 13. Test strategy

Implementation proceeds test-first.

The test suite must establish, independently:

1. Exact baseline contradiction path `E1` through `E6` and terminal `a1`.
2. Canonical serialization and byte-identical arm forks before intervention.
3. Normal capability workload correctness and strictly lower A cost.
4. A optimizer API has only permitted normal-workload inputs.
5. Deliberate corrective-artifact contamination produces `OPTIMIZATION_LEAKAGE`.
6. C preserves the qualified corrective route.
7. E closes scope through `VALID_SCOPE_CLOSURE` and cannot masquerade as A.
8. Warrant in A reaches `CORRECTION` before any downstream route loss.
9. Trace hash chaining detects mutation or deletion.
10. Unique first-missing-edge localization works and ambiguous localization stops.
11. Every frozen decision rule has at least one direct unit test.
12. Positive and clean-null fixtures are classifier tests only until the real assay is executed; they are not scientific results.

The implementation is not complete until all tests pass from a clean checkout.

## 14. Commit and execution separation

Repository history preserves the scientific sequence:

```text
commit 1: frozen protocol + implementation design
commit 2: faithful implementation + tests
future step: assay execution + custody/trace/result artifacts
```

The implementation commit must not modify the bytes of any frozen preregistration artifact. Before implementation is declared complete, their repository bytes must reproduce the preregistered SHA-256 values.

## 15. Claim discipline

Software completion is not a scientific result. Passing tests establish that the implementation matches the frozen software contract; they do not establish adaptive foreclosure.

Only a later protocol-valid execution may be mechanically classified, and even a positive result is bounded by the frozen claim ceiling. A null remains informative and does not reopen the protocol for tuning.
